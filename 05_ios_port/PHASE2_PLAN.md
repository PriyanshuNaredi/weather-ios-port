## 2. SDK extraction requirements (verified flow)
1. `xtool setup` → login mode `1: Password (works with any Apple ID but uses private APIs)` → **STOP: user completes credentials interactively**.
2. Same prompt asks `Path to Xcode.xip:` → user supplies path to the XIP they downloaded.
3. xtool extracts the XIP and generates/installs an iOS Swift SDK; verify with `swift sdk list` → `darwin`.
4. First `xtool dev` builds iOS SDK Swift modules (slow, minutes) then caches globally.

## 3. Free-account signing limitations (Apple policy + xtool docs)
- Password mode uses **private Apple APIs** — xtool docs recommend considering a throwaway Apple ID; user's credentials go only to Apple (verifiable by building xtool from source).
- Free (personal team) provisioning, per Apple's standard rules: apps **expire after 7 days** and must be re-signed/installed; **max 3 App IDs**; **10 app limit** per device; device must be registered; Developer Mode must be enabled on the iPhone.
- xtool automates: device registration → certificate → App ID → provisioning profile → codesign → install.
- Bundle ID for our port must be something like `dev.kiankonrad.weather.ios` (1 of the 3 free App-ID slots).

## 4. USB passthrough requirements (WSL2)
- **usbipd-win** on Windows (Microsoft official: `winget install usbipd`; requires admin) to bind the iPhone's USB device to WSL.
- **usbmuxd** inside Ubuntu (`sudo apt-get install usbmuxd` + `libimobiledevice-utils` for `ideviceinfo`) — **this is the one required Ubuntu package installation; will ask before running**.
- Known pitfall (xtool docs): `AFCClient.Error.muxError` on WSL — documented workaround relays the device connection through iTunes on Windows instead of USBIPD (xtool issue #19).
- Alternative if USBIPD proves flaky: produce the signed IPA and install it via Apple Configurator/Finder on any PC/Mac, or on-device methods — no Linux USB needed.

## 5. Expected IPA build process (per xtool First-app tutorial)
1. `xtool new` → SwiftPM package + `xtool.yml` (Bundle ID) + BSP config.
2. Port code into `Sources/` (SwiftUI app).
3. `xtool dev` → SwiftPM builds against the iOS SDK → xtool registers device, makes cert/App ID/profile, signs, installs on USB-connected iPhone, launches.
4. IPA artifact also exportable via xtool install/uninstall/launch subcommands → kept in `06_build_artifacts/ipa/`.
5. On-device first-launch steps (user performs): Trust dialog, Developer Mode, Settings→General→VPN & Device Management→Trust certificate.

## 6. Potential xTool/SwiftUI compatibility issues
- **MapKit**: MapKit is Apple's framework and ships in the iOS SDK, so SwiftUI `Map` compiles against the SDK; but the Linux-side build server has no visual preview — UI iterations require device round-trips.
- Dark map: MapKit has no OpenFreeMap equivalent; closest is `MKStandardMapConfiguration(emphasisStyle: .muted)` + dark `overrideUserInterfaceStyle` + custom point-of-interest filtering. **Documented difference from Android MapLibre dark style**; radar overlay via `MKTileOverlay` with RainViewer tiles (raster) is feasible.
- Swift 6.4 strict concurrency may surface warnings when porting the callback-style `LocationManager` code — plan for async/await `CLLocationUpdate.liveUpdates()` (iOS 17+) instead.
- The app uses no third-party iOS deps, minimizing SwiftPM-on-Linux risk. Compose→SwiftUI chart: SwiftUI `Canvas` maps 1:1.
- Free-account 7-day expiry: installed apps stop launching weekly until re-signed — acceptable for a port evaluation, not for daily use.

## 7. Rollback procedure
- Everything portable: delete `07_tools/xtool`, `07_tools/swift-linux`, `07_tools/xcode`, SDK cache dir, and the xtool config (`~/.config/xtool` or equivalent — path recorded when created) → zero residue.
- Ubuntu packages added (usbmuxd, libimobiledevice-utils): `sudo apt-get remove --purge usbmuxd libimobiledevice-utils`.
- Windows side: usbipd-win uninstallable via `winget uninstall usbipd` (only if we installed it — not yet).
- No macOS, no App Store publishing, no system-wide env vars touched. iPhone removal: long-press → delete app, plus Settings→VPN & Device Management→Delete Profile.
